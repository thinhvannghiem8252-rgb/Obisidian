  * ==**传感器（Sensors）**==：智能体获取外部环境状态的输入物理通道（例如摄像头、红外测距仪、内窥镜、触觉/力反馈传感器）。

### 4. 效用函数（Utility Function）与最大期望效用（MEU）
* **效用函数 $U(s)$**：状态 $s \rightarrow \mathbb{R}$。是==将 PEAS 框架中的抽象性能度量转化为**可直接用于数学计算的标量打分机==制**（收益打正分，风险/代价/损伤打负分）。
* **反射式智能体 vs 问题求解智能体**：
  * **反射式智能体（Reflex Agent）**：直接根据当前瞬间的感知输入执行硬编码条件-动作规则（如：`if status == Dirty then return Clean`；遇到障碍物直接被动转向），不前瞻评估后续步骤的长远后果。
  * **问题求解智能体（Problem-solving Agent）**：目标导向；在物理执行前，先在内部符号模型中模拟各种候选动作序列并推演未来后果，评估能否到达目标状态。“**先离线规划，再在线执行**”。
* **期望效用与决策准则（MEU）**：
  ==在转移结果存在不确定性时，依据可能出现的结果状态概率计算加权平均，并坚决选择期望效用最大的行动：==
  $$EU(a) = \sum_{s'} P(s' \mid s, a) \cdot U(s')$$
  $$a^* = \arg\max_a EU(a)$$
  *理性并非要求思维过程“像人类大脑”，而是指遵循严密、可计算的效用最大化数学准则。*

### 5. 搜索问题形式化五要素（Formal Problem Formulation）
任何经典的规划与路径搜索任务，都必须严格数学抽象为以下五要素：
1. ==**初始状态==（Initial State, $S_0$）**：智能体启动规划时所处的最初状态配置（例如：迷宫入口网格 $(1, 1)$；穿刺手术进针点的皮肤坐标）。
2. ==**动作集合==（Actions, $Actions(s)$）**：在状态 $s$ 下允许智能体执行的所有合法操作集合（例如：在无障碍网格中可执行 $\{\text{上}, \text{下}, \text{左}, \text{右}\}$）。
3. ==**转移模型==（Transition Model, $Result(s, a)$）**：一个形式化转移函数，定义在状态 $s$ 执行动作 $a$ 后转移产生的后继新状态 $s'$，障碍物与物理壁垒约束隐含其中（例如：$Result((1, 1), \text{右}) = (1, 2)$）。
4. ==**目标测试==（Goal Test）**：布尔判断函数，检验当前状态是否满足任务终止的目标要求（例如：当前坐标是否等于出口 $(10, 10)$；穿刺针尖是否精确进入靶肿瘤内部）。
5. ==**单步代价==（Action Cost / Step Cost, $c(s, a, s')$）**：从状态 $s$ 经过动作 $a$ 抵达 $s'$ 所消耗的资源成本（例如：行进一步代价为 $1$；若穿越易出血高风险器官区域，则代价设为高惩罚值）。

## 模块二：状态空间、图搜索框架与评价参数

### 1. 状态空间与组合爆炸
* **状态空间（State Space）**：由初始状态出发，通过任意合法动作序列所能到达的所有可能状态配置的集合。
  * 状态空间可形式化表示为**有向图（Directed Graph）**：节点（Node）代表具体状态，有向边（Edge）代表动作转移。
  * *小规模案例*：双房间吸尘器世界，2 个位置 $\times 2^2$ 种灰尘分布 $= 8$ 种状态，可轻易手绘展开。
* **组合爆炸（Combinatorial Explosion）**：==实际工程与科学问题的状态空间随变量规模呈阶乘或指数级暴增：==
  * **8-Puzzle（8-拼图）**：$\frac{9!}{2} = 181,440 \approx 1.8 \times 10^5$ 状态（现代计算机毫秒级穷举）。
  * **15-Puzzle（15-拼图）**：$\frac{16!}{2} \approx 1.05 \times 10^{13}$ 状态（仅存储图节点就需要约 $160\text{ TB}$ 内存）。
  * **24-Puzzle（24-拼图）**：$\frac{25!}{2} \approx 7.7 \times 10^{24}$ 状态（数量级超过全宇宙可见恒星总数！）。
  * **分子对接（Molecular Docking，生医工经典问题）**：小分子配体对接靶点受体结合口袋（如 $\beta_2$ 肾上腺素受体 PDB 3SN6），6 个空间位姿自由度 $+ 10$ 个可旋转共价键，构象空间高达 $36^{16} \approx 10^{24}$，与 24-拼图同等量级。
* **搜索的核心工程法则**：==面对天量状态空间，**必须采用隐式表示（Implicit Representation），按需局部展开（Expand on Demand），绝对不能预先在内存中构建全图！**==

### 2. 状态空间图 vs 搜索树
* **状态空间图（State Space Graph）**：是问题本身的**静态客观地图**，同一个物理状态在图中仅出现一次，图往往包含回路（Cycles）。
* **搜索树（Search Tree）**：是智能体对状态空间进行搜索规划的**动态探索轨迹**。
  * 树的边对应转移动作，根节点为初始状态。
  * **树节点（Node）包含丰富的搜索上下文数据结构**：==包含当前状态标识、指向父节点的指针、生成该节点的动作、从根到达该节点的**累积路径代价 $g(n)$** 及节点深度。==
  * 不同的树节点可以对应状态空间中的同一个物理状态（代表通过不同的探索路径抵达该状态）。

### 3. 通用图搜索算法框架（Graph Search）
为了防止在有环图中陷入死循环并避免重复搜索相同状态，图搜索在树搜索的基础上维护了一个已访问集合（Explored Set / Closed List）：

```
function GRAPH-SEARCH(problem) returns a solution path, or failure
    Initialize:
        Frontier ← 优先队列/队列/栈，初始包含由 problem.InitialState 构造的根节点
        Explored ← 空集合 (用于记录所有已经展开过的物理状态)
    
    loop do:
        if Frontier is empty then return failure
        
        node ← Frontier.Pop()    // 依据具体搜索策略选择一个节点出队
        
        if problem.GoalTest(node.State) then return Solution(node)
        
        Explored.Add(node.State) // 将当前状态标记为已处理
        
        for each action in problem.Actions(node.State) do
            child ← ChildNode(problem, node, action)
            if child.State is not in Explored and child.State is not in Frontier then
                Frontier.Insert(child)
            else if child.State is in Frontier with higher path cost then
                // 如果发现到达 Frontier 中同一状态的更优路径，更新其代价与父指针
                Frontier.Update(child)
```

> **图搜索的核心精髓**：==**Graph Search = Frontier 选择候选 + Explored 集合去重**==。所有具体搜索算法的唯一本质差异，仅在于其定义**“下一个从 Frontier 中挑选谁来展开”**的优先级策略函数。

### 4. 路径代价重开问题（Cost Reopening）
在带权图搜索中，引入 Explored 集合虽然能彻底阻断循环，但带来了一个关键隐患：
* **问题**：如果算法后续经由另一条迂回但总代价更低的路径再次抵达了某个已经被记录在 Explored 集合中的状态 $X$（即先发现路径 $g_1(X) = 5$，后发现更优路径 $g_2(X) = 3$），简单地将其作为重复状态丢弃将**破坏算法的最优性**！
* **解决对策**：必须支持代价重开（Cost Reopening，将 $X$ 从 Explored 移回 Frontier 重新更新）或者从数学上保证启发函数满足**一致性（Consistency）**，从而确保任何状态首次出队展开时即为全局最优路径。

### 5. 搜索算法的四项形式化评价标准与复杂度参数
![image.png](https://cdn.jsdelivr.net/gh/thinhvannghiem8252-rgb/Obisidian@main/img/20261019092915979.png)

* **树参数定义**：
  * $b$：**分支因子（Branching Factor）**，搜索树中每个节点所拥有的最大合法后继分支数。
  * $d$：**最浅目标深度（Depth of Shallowest Goal）**，从根节点到最浅有效目标状态的==最少边数==。
  * $m$：**最大搜索深度（Maximum Depth）**，状态空间中==任意可能探索路径的最大深度==（在含环或无限空间中 $m \rightarrow \infty$）。
  * $C^*$：目标状态的**最优路径代价**。
  * $\varepsilon$：图中单步动作的**最小代价正下界**（$\forall a, c(s, a, s') \ge \varepsilon > 0$）。
* **四大评价维度**：
  1. **完备性（Completeness）**：当问题确实存在可行解时，算法是否保证在有限步内一定能找到解？
  2. **最优性（Optimality）**：算法输出的解路径，是否保证是所有可行解中累积总路径代价最低的解？
  3. **时间复杂度（Time Complexity）**：算法在搜索过程中所生成/展开的节点总数。
  4. ==**空间复杂度（Space Complexity）**：算法在搜索全周期内内存中必须同时缓存的最大节点数==（通常取决于 Frontier + Explored 的峰值体量）。

## 模块三：无信息（盲目）搜索算法（Uninformed Search）

无信息搜索只利用问题五要素本身给出的信息，**无法预估当前节点离最终目标究竟还有多远**，展开完全按预定拓扑规则推进。

```
           ┌─── 广度优先 (BFS) ─── FIFO 队列 ── 逐层波纹推进，保最浅解，内存极高 O(b^d)
           │
           ├─── 深度优先 (DFS) ─── LIFO 栈 ──── 一钻到底快速试错，空间极致线性 O(bm)，不保最优
无信息搜索 ┼
           ├─── 迭代加深 (IDS) ─── 逐层增深 ── 深度受限 DFS 递归，BFS 时间 + DFS 空间，盲搜首选
           │
           └─── 一致代价 (UCS) ─── 优先队列 ── 按 g(n) 升序，Dijkstra 本质，保不等代价最优解
```

---

### 1. 广度优先搜索（BFS, Breadth-First Search）
* **展开策略**：从起点开始逐层向外平推，如同水面波纹，==在访问第 $k+1$ 层的任何节点之前，必须完全访问并展开第 $k$ 层的全部节点==。
* **数据结构**：先进先出队列（**FIFO Queue**）。先发现的节点先入队，先出队展开。
* ![image.png](https://cdn.jsdelivr.net/gh/thinhvannghiem8252-rgb/Obisidian@main/img/20261019093723514.png)

* **性能指标**：
  * **完备性**：$\checkmark$（只要分支因子 $b$ 有限，必然能逐层下探遍历到最浅目标层 $d$）。
  * **最优性**：**仅当所有单步动作代价均相等时最优**（找到边数最少的解；在不等单步代价下不保证最优）。
  * **时间复杂度**：$O(b^d)$（第 $d$ 层节点数为 $b^d$）。
  * **空间复杂度**：$O(b^d)$（**致命硬伤**！Frontier 必须同时在内存中缓存整整一层的所有叶子节点）。
* **评价**：内存消耗呈指数级膨胀，在现实大规模搜索问题中往往先于算力耗尽服务器物理内存。

---

### 2. 深度优先搜索（DFS, Depth-First Search）
* **展开策略**：==沿当前分支持续向深层挺进，只有当遭遇死胡同无法继续或触发深度限制时，才回溯到最近的分叉口探索兄弟分支。==
* **数据结构**：后进先出栈（**LIFO Stack**）或递归系统调用栈。“最新分支，优先深入”。
* **性能指标**：
  * **完备性**：$\times$（在状态空间无限、或者存在未去重环路的状态空间中，极易陷入无穷深度的死分支而无法回溯）。
  * **最优性**：$\times$（可能碰巧沿深层分支命中一个代价极高、迂回复杂的劣解而提前终止）。
  * **时间复杂度**：$O(b^m)$（在最差情况下可能遍历完整棵深达 $m$ 的庞大搜索树）。
  * **空间复杂度**：**$O(bm)$（极致轻量化核心优势！）**。内存中只需要保留当前从根到叶的单条活跃路径（长为 $m$）以及沿途节点尚未展开的同级兄弟节点（每层最多 $b$ 个）。
* **评价**：空间极其节省，但鲁棒性差，存在==死循环和找差解的巨大风险。==

---

### 3. 迭代加深搜索（IDS, Iterative Deepening Search）
* **设计动机**：能否同时兼得 **BFS 的完备性与最优性** 以及 **DFS 的极低空间复杂度**？
* **工作机制**：
  * 循环调用深度受限搜索（DLS, Depth-Limited Search），将深度截断阈值 $i$ 从 $0, 1, 2, \dots$ 逐轮递增。
  * 每一轮均从根节点完全重启一次受限 DFS；若在当前深度上限 $i$ 内未发现目标，则抛弃整棵搜索树，将限制增大为 $i+1$，重新从根启动展开。
* **浅层节点重复计算的开销分析（核心考点推导）**：
  直觉上每一轮重构会导致大量重复计算，但数学证明该开销非常小。设最浅目标深度为 $d$：
  * 根节点（深度 0）被展开 $d + 1$ 次；
  * 深度 1 节点被展开 $d$ 次，共 $d \times b$ 个；
  * 深度 $d$ 节点仅被展开 1 次，共 $1 \times b^d$ 个。
  * 总节点展开总数：
    $$N_{IDS} = (d+1) \cdot 1 + d \cdot b + (d-1) \cdot b^2 + \dots + 1 \cdot b^d = \sum_{i=0}^d (d - i + 1) b^i$$
  * 渐进比例极限：
    $$\frac{N_{IDS}}{b^d} \approx \frac{b}{b - 1}$$
    当常见分支因子 $b = 10$ 时，$\frac{10}{9} \approx 1.11$。即**全过程总计算量仅比单次理想展开多了约 $11\%$ 的微小代价**，但换来了空间从不可承受的 $O(b^d)$ 锐减至微小的 $O(bd)$！
* **性能指标**：
  * **完备性**：$\checkmark$（分支因子 $b$ 有限时完备）。
  * **最优性**：$\checkmark$（单步等代价时必然最先在最浅深度 $d$ 找到最优解）。
  * **时间复杂度**：$O(b^d)$（与 BFS 同量级）。
  * **空间复杂度**：**$O(bd)$（与深度 $d$ 呈线性关系）**。
* **权威结论**：**在无先验启发信息的大规模状态空间中，IDS 是综合表现最优秀的盲目搜索算法！**

---

### 4. 一致代价搜索（UCS, Uniform-Cost Search）
* **设计动机**：当图中各边步长转移代价**不相等**时（如高速公路 vs 盘山小路），BFS 找到的边数最少路径不再等于累积总代价最小路径。
* **工作机制**：
  * 将 BFS 队列升级为**优先队列（Priority Queue）**，排序键严格设定为从起点到当前节点的**实际累积路径代价 $g(n)$**。
  * 算法始终挑出当前全局 $g(n)$ 最小的节点予以展开。
  * **搜索波前表现**：在带权拓扑平面上，搜索边界呈不规则的“等代价同心轮廓线（犬牙交错状）”向外均匀扩展。
  * **算法本质**：UCS 本质上是图论中经典 **Dijkstra 最短路径算法（1959）** 在隐式状态空间中的在线搜索实现；BFS 是其所有单步权值 $c=1$ 时的退化特例。
* **两大关键执行准则（考试高频易错点！）**：
  1. **目标测试时机：必须在目标节点从 Frontier“出队（Pop）”时进行判定，绝对不能在它被子节点“生成入队（Insert）”时提前判定！**
     * *原因*：当前生成的后继即便直达目标，其路径总代价可能依然高于 Frontier 中某条尚未延伸的潜在优质路径。过早终止会错失全局更优解。
  2. **权值必须严格正：单步动作代价必须存在正下界 $\varepsilon > 0$（即 $c(s, a, s') \ge \varepsilon > 0$）**。
     * *原因*：若存在零代价边甚至负边，算法可能在零代价环路上打转无限生成节点，导致完备性与最优性崩溃。
* **性能指标**：
  * **完备性**：$\checkmark$（只要 $\varepsilon > 0$）。
  * **最优性**：$\checkmark$（沿非减等代价线扩展，首个被选出出队的目标节点必定是最优解）。
  * **时空复杂度**：$O\left(b^{1 + \lfloor C^* / \varepsilon \rfloor}\right)$（记作 $O(b^{C^*/\varepsilon})$，其中 $C^*$ 为最优解代价）。当代价差异悬殊时可能非常庞大。

---

## 模块四：有信息（启发式）搜索与 A* 黄金标准

有信息搜索引入了**启发函数 $h(n)$（Heuristic Function）**，打破无头苍蝇般的盲目扩张，赋予搜索算法向目标挺进的明晰“方向感”。

### 1. 启发函数 $h(n)$ 的本质与设计准则
* **定义**：$h(n) = \text{评估节点 } n \text{ 到目标状态的估计剩余最小路径代价}$（且 $h(Goal) = 0$）。
* **物理示例**：
  * **城市导航地图**：两城市之间的空间**直线欧氏距离（Straight-line Distance）**用作道路真实行车里程的下界启发估计。
  * **微创手术机器人穿刺规划**：当前探针尖端坐标到靶器官病灶中心点的三维空间**直线欧氏距离**，用作穿刺路径绕行解剖障碍物所需剩余代价的启发估计。
* **量纲统一铁律**：**启发函数 $h(n)$ 必须与实际累积代价 $g(n)$ 采用完全相同的度量衡与物理量纲！**（若 $g(n)$ 是物理距离公里数，$h(n)$ 绝不能是通行时间分钟数，否则无法相加构成联合评估）。

---

### 2. 贪心最佳优先搜索（Greedy Best-First Search）
* **核心哲学**：“**只看未来，不顾过去**”。
* **评估函数**：
  $$f(n) = h(n)$$
* **机制与缺陷**：
  * 优先队列完全依据 $h(n)$ 从小到大排序。算法展现出强烈的直奔目标的冲动。
  * **短视致命风险**：由于完全无视已经付出的累积代价 $g(n)$，启发函数局部的微小误导就可能将搜索诱入死胡同、悬崖或巨幅绕远弯路（见下文罗马尼亚实例）。
* **性能指标**：
  * **完备性**：$\times$（树搜索中若有环可能死循环；图搜索在有限空间中完备，但在无限空间中不完备）。
  * **最优性**：$\times$（找到的往往不是最低代价解）。
  * **时空复杂度**：最差情况下退化为 $O(b^m)$。

---

### 3. A* 搜索算法（A-Star Search, Hart, Nilsson & Raphael, 1968）
* **核心哲学**：“**统筹兼顾，兼听过去与未来**”。
* **评估函数（黄金组合）**：
  $$f(n) = g(n) + h(n)$$
  * $g(n)$：**过去实际已知代价**（起点到当前节点 $n$ 的确切真实路径消耗）。
  * $h(n)$：**未来启发预测代价**（当前节点 $n$ 到目标的预估剩余消耗）。
  * $f(n)$：**经由节点 $n$ 到达目标的估计总路径代价**。
* **机制本质**：
  * **A\* = 一致代价搜索 (UCS) + 启发引导 (Heuristic Guidance)**。
  * 排序键由单纯的 $g(n)$ 进化为综合的 $f(n)$。若 $h(n) = 0$，A* 算法精确退化为 UCS；一个优良的 $h(n)$ 会像重力场一样将搜索椭球体精准“拉扯”向目标方向，极大削减盲目扩散的搜索横截面积。

---

### 4. 经典实例详细推演：罗马尼亚度假问题（Arad $\rightarrow$ Bucharest）

各城市到目标 Bucharest 的直线距离启发式 $h(n)$ 查表如下：
* Arad: 366 | Bucharest: 0 | Craiova: 160 | Dobreta: 242 | Eforie: 161 | Fagaras: 178 | Giurgiu: 77 | Hirsova: 151
* Iasi: 226 | Lugoj: 244 | Mehadia: 241 | Neamt: 234 | Oradea: 380 | Pitesti: 98 | Rimnicu Vilcea: 193
* Sibiu: 253 | Timisoara: 329 | Urziceni: 80 | Vaslui: 199 | Zerind: 374

#### 贪心搜索推演过程（$f = h$）：
1. 初始节点 Arad ($h=366$) 出队展开，后继：Sibiu ($h=253$), Timisoara ($h=329$), Zerind ($h=374$)。
2. 最小为 **Sibiu ($h=253$)**，出队展开，后继：Fagaras ($h=178$), Rimnicu Vilcea ($h=193$), Oradea ($h=380$), Arad ($h=366$)。
3. 最小为 **Fagaras ($h=178$)**，出队展开，后继：Sibiu ($h=253$), Bucharest ($h=0$)。
4. 最小为 **Bucharest ($h=0$)**，出队，搜索结束！
* **贪心路径**：$\text{Arad} \rightarrow \text{Sibiu} \rightarrow \text{Fagaras} \rightarrow \text{Bucharest}$。
* **实际总代价**：$140 + 99 + 211 = \mathbf{450}$（**非最优劣解！**）。

#### A* 搜索推演过程（$f = g + h$）：
1. 初始 Arad ($g=0, h=366 \rightarrow f=366$) 出队展开：
   * Sibiu: $g=140, h=253 \rightarrow f=393$
   * Timisoara: $g=118, h=329 \rightarrow f=447$
   * Zerind: $g=75, h=374 \rightarrow f=449$
   * *当前队列最小*：**Sibiu ($f=393$)**。
2. 选出 **Sibiu ($f=393$)** 出队展开：
   * Rimnicu Vilcea: $g=140+80=220, h=193 \rightarrow f=413$
   * Fagaras: $g=140+99=239, h=178 \rightarrow f=417$
   * *当前队列最小*：**Rimnicu Vilcea ($f=413$)**（注：小于 Fagaras 的 417）。
3. 选出 **Rimnicu Vilcea ($f=413$)** 出队展开：
   * Pitesti: $g=220+97=317, h=98 \rightarrow f=415$
   * Craiova: $g=220+146=366, h=160 \rightarrow f=526$
   * *当前队列最小*：**Pitesti ($f=415$)**。
4. 选出 **Pitesti ($f=415$)** 出队展开：
   * Bucharest: $g=317+101=418, h=0 \rightarrow f=418$
   * *当前队列最小*：Fagaras ($f=417$)，展开后继无更优解。
5. 最终 **Bucharest ($f=418$)** 作为队列全局最小值出队，输出最优解！
* **A\* 最优路径**：$\text{Arad} \rightarrow \text{Sibiu} \rightarrow \text{Rimnicu Vilcea} \rightarrow \text{Pitesti} \rightarrow \text{Bucharest}$。
* **实际最优总代价**：$140 + 80 + 97 + 101 = \mathbf{418}$（**成功避开贪心陷阱，寻获全局最优解！**）。

## 模块五：A* 最优性理论与启发函数构造

A* 算法的最优性并非无条件的，它对启发函数 $h(n)$ 提出了两大约束性质：

### 1. 可采纳性（Admissibility）与一致性（Consistency）

```
     ┌────────────────────────┐
     │  一致性 (Consistency)   │ ===> 必然蕴含 ===> ┌─────────────────────────┐
     │  h(n) ≤ c(n,a,n') + h(n')│                   │ 可采纳性 (Admissibility)  │
     └────────────────────────┘                   │     h(n) ≤ h*(n)        │
                 │                                └─────────────────────────┘
                 │                                             │
                 ▼                                             ▼
        【图搜索 A* 保证最优】                         【树搜索 A* 保证最优】
        每个状态首次出队即最优                         需可采纳即可，图搜可能重开
```

#### (1) 可采纳性（Admissibility）
* **数学定义**：对于搜索树中的任意节点 $n$，均有：
  $$h(n) \le h^*(n)$$
  其中 $h^*(n)$ 表示从节点 $n$ 到达目标状态的真实最低剩余代价。
* **直观含义**：启发函数是**“乐观估计”（Optimistic / Never Overestimates）**，即估计值永远不会超过实际真实代价。
* **理论定理**：在**树搜索（Tree Search）**架构中，只要 $h(n)$ 满足可采纳性，A* 算法保证返回最优解。
* **直观证明思路**：假设存在次优目标 $G_2$（实际代价 $g(G_2) > C^*$）在最优解 $G$ 出队前被展开。因为最优路径上必存在未展开的边界节点 $n$，其 $f(n) = g(n) + h(n) \le g(n) + h^*(n) = C^* < g(G_2) = f(G_2)$，优先队列必定优先弹出 $n$ 深入扩展，绝不可能让 $G_2$ 提前出队。

#### (2) 一致性（Consistency / Monotonicity，单调性）
* **数学定义**：对于任意节点 $n$ 及其任意动作后继 $n'$，启发函数必须满足**广义三角不等式**：
  $$h(n) \le c(n, a, n') + h(n')$$
  且目标状态 $h(Goal) = 0$。
* **直观含义**：从节点 $n$ 到目标的估计剩余代价，不能大于单步转移代价加上后继 $n'$ 到目标的估计剩余代价。沿任意路径行进时，总估计代价函数 $f(n)$ **单调非减**（即 $f(n') = g(n') + h(n') = g(n) + c(n, a, n') + h(n') \ge g(n) + h(n) = f(n)$）。
* **理论定理**：在**图搜索（Graph Search）**架构中，若 $h(n)$ 满足一致性，则**任何节点首次从 Frontier 中出队时，其记录的路径代价 $g(n)$ 已经必然是全局最优路径！**
* **重大工程价值**：一旦 $h(n)$ 一致，图搜索在把节点放入 Explored 集合后，**完全不需要执行复杂的“代价重开（Cost Reopening）”逻辑**，大幅简化算法实现并提升执行效率。

#### (3) 核心关系辨析
* **一致性 $\implies$ 可采纳性**（一致性要求更高，是一致性的充分条件）。
* **可采纳性 $\not\implies$ 一致性**（存在可采纳但非一致的启发函数）。
* 地图导航中的空间直线欧氏距离，天然同时满足一致性与可采纳性。

---

### 2. 放松问题构造启发函数（Relaxed Problems）
如何科学、系统化地设计出保证可采纳的 $h(n)$？
* **核心方法论**：**构造放松问题（Relaxed Problem）** —— 移除原问题中的一个或多个物理约束条件。
* **核心定理**：**放松后简化问题的最优解路径代价，在数学上必然小于或等于原真实问题的最优解代价！** 因此，任何放松问题的精确解代价，天然构成原问题的可采纳启发函数 $h(n)$。
* **以 8-Puzzle（8-拼图）为例**：
  * **原问题约束**：一个棋子只能移动到与其正交相邻的空格子中。
  * **放松方案 1 $\rightarrow$ 启发函数 $h_1$（错位棋子数, Misplaced Tiles）**：
    * *放松约束*：“允许棋子不受空格阻挡、直接一步瞬移跳入目标槽位”。
    * *定义*：不在目标最终位置的棋子总个数。
    * *实例计算*：若当前盘面有 6 个棋子不在目标槽位，则 $h_1 = 6$。
  * **放松方案 2 $\rightarrow$ 启发函数 $h_2$（曼哈顿距离和, Manhattan Distance Sum）**：
    * *放松约束*：“允许棋子在网格线上自由滑动，即使相邻格子里已有棋子也不受物理阻挡”（去除了方块互斥阻挡约束）。
    * *定义*：所有棋子从当前网格坐标 $(x_1, y_1)$ 移动到各自目标坐标 $(x_2, y_2)$ 的曼哈顿距离总和：
      $$h_2 = \sum_{i=1}^8 \left(|x_{i} - x_{i, goal}| + |y_{i} - y_{i, goal}|\right)$$
    * *实例计算*：各棋子曼哈顿距离相加为 $14$。
  * **验证与真实值**：设该实例的真实最优移动步数为 $h^* = 20$。
    $$h_1 = 6 \le h^* = 20, \quad h_2 = 14 \le h^* = 20$$
    两者均严格满足 $h \le h^*$（可采纳）。
* **设计哲理**：**放宽的约束越多 $\rightarrow$ 启发估计值越小 $\rightarrow$ 算法越乐观，但信息量越弱；保留的约束越多 $\rightarrow$ 启发估计值越紧致逼真 $\rightarrow$ A* 展开节点越少。**

---

### 3. 启发函数的支配性与进阶方法
* **支配性（Dominance）**：
  * **定义**：设有两个可采纳启发函数 $h_1(n)$ 和 $h_2(n)$，若对于状态空间中的所有节点 $n$，均满足：
    $$h_2(n) \ge h_1(n)$$
    则称 **$h_2$ 严格支配（Dominates）$h_1$**。
  * **意义**：$h_2$ 的估计值处处比 $h_1$ 更高且不超标（更接近真实值 $h^*(n)$），利用了更多有效先验信息。
  * **结论**：**使用支配启发函数 $h_2$ 的 A\* 算法，其展开的搜索节点总数必定少于或等于使用 $h_1$ 的节点数！**（8-拼图中，曼哈顿距离 $h_2$ 处处大于等于错位棋子数 $h_1$，故 $h_2$ 严格支配 $h_1$）。
* **组合启发（Max Combination）**：
  * 若面对多个互不支配的可采纳启发函数 $h_1, h_2, \dots, h_k$（某些状态下 $h_1$ 更大，另一些状态下 $h_2$ 更大）；
  * 直接取上确界复合：
    $$h(n) = \max\left(h_1(n), h_2(n), \dots, h_k(n)\right)$$
  * **性质**：复合后的 $h(n)$ 依然**严格满足可采纳性与一致性**，并且**同时支配所有单一分量启发函数**。
* **模式数据库（Pattern Database, PDB）**：
  * 针对原问题的子集模式（如 8-puzzle 中只观察 $1, 2, 3, 4$ 四个棋子），离线反向搜索出所有子状态到目标的精确最小步数，预存入哈希数据库。
  * 在线搜索时直接查表作为启发值。因为忽略了其余棋子的阻挡，查表值绝不高估，保证可采纳且精度极高。
* **学习型启发（Learned Heuristics）**：
  * 当状态空间极度复杂、无法推导几何解析式时，使用深层神经网络或强化学习从大规模历史状态样本中回归出估值网络。
  * **典型案例**：**AlphaGo** 的价值网络（Value Network），输入棋盘特征，输出胜率预估，作为蒙特卡洛树搜索（MCTS）中高层剪枝的启发估值函数。

## 模块六：六大搜索算法综合对比与选择决策指南

### 1. 六大算法核心性能全景对比表

| 算法名称 | 完备性 | 最优性 | 时间复杂度 | 空间复杂度 | 核心驱动数据结构 / 关键特征 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **BFS<br>(广度优先)** | $\checkmark$（$b$ 有限） | $\checkmark$（等代价） | $O(b^d)$ | $O(b^d)$ | **FIFO 队列**<br>逐层展开，保证最浅解，内存消耗极大 |
| **DFS<br>(深度优先)** | $\times$（无限空间） | $\times$ | $O(b^m)$ | **$O(bm)$** | **LIFO 栈**<br>空间极度节省（线性），易陷入死循环或劣解 |
| **IDS<br>(迭代加深)** | $\checkmark$（$b$ 有限） | $\checkmark$（等代价） | $O(b^d)$ | **$O(bd)$** | **循环深度受限栈**<br>兼得 BFS 的完备/最优与 DFS 的线性极低内存 |
| **UCS<br>(一致代价)** | $\checkmark$（$\varepsilon > 0$） | $\checkmark$（$c > 0$） | $O(b^{C^*/\varepsilon})$ | $O(b^{C^*/\varepsilon})$ | **优先队列按 $g(n)$ 排序**<br>Dijkstra 本质，处理非等代价最优解，出队才判目标 |
| **贪心最佳优先<br>(Greedy)** | $\times$（含环时） | $\times$ | $O(b^m)$ | $O(b^m)$ | **优先队列按 $h(n)$ 排序**<br>只看未来预估，速度极快但极易被误导，不保解质量 |
| **A\* 搜索<br>(黄金标准)** | $\checkmark$（$\varepsilon > 0$） | **$\checkmark$（需可采纳/一致）** | 取决于 $h$ 精度<br>最坏 $O(b^d)$ | $O(b^d)$ | **优先队列按 $f = g + h$ 排序**<br>结合过去成本与未来预估，平衡效率与最优性 |

> **关键符号速查**：$b$ = 分支因子；$d$ = 最浅解深度；$m$ = 最大探索深度；$C^*$ = 全局最优解代价；$\varepsilon$ = 单步最小代价下界。

### 2. 算法选型决策树与实战口诀

```
                                需要全局最优解吗？
                                   /          \
                                 是            否
                                /                \
                         有可靠启发函数吗？       【贪心最佳优先搜索】
                          /           \          (速度极快，保证无环或加 Explored)
                        是             否
                       /                 \
                  【A* 搜索】         状态空间规模大吗？
               (需满足可采纳/一致)      /        \
                                     小            大
                                    /                \
                              单步代价相等吗？     【迭代加深搜索 (IDS)】
                                /        \         (空间线性 O(bd)，兼顾完备最优)
                              是          否
                             /              \
                        【BFS】           【UCS】
                    (FIFO 队列)    (优先队列按 g 排序 / Dijkstra)
```

* **选型速记黄金口诀**：
  * **贪心快而不优**（追求极速出解，不计成本）；
  * **BFS 专攻等代价**（边权全为 1，寻找最浅步数）；
  * **UCS 变代价称王**（边权各异，无启发信息下的最优兜底）；
  * **内存告急用 IDS**（盲目搜索遇到内存瓶颈时的终极利器）；
  * **启发寻路必选 A\***（有启发先验且追求最优解的标准解法）。

## 模块七：期末复习与自测高频考点清单

| 考点序号 | 核心考点设问 | 考点核心核对要点（采分点） |
| :---: | :--- | :--- |
| **Q1** | 搜索问题形式化建模的五要素是什么？ | ① 初始状态 $S_0$；② 合法动作集 $Actions(s)$；③ 状态转移模型 $Result(s, a)$；④ 目标测试函数 $Goal(s)$；⑤ 单步路径代价 $c(s, a, s')$。 |
| **Q2** | 解释状态空间图与搜索树的本质区别？ | 状态空间图是静态地图（节点唯一，常有环）；搜索树是动态探索轨迹（节点含路径与 $g(n)$，不同树节点可对应同一物理状态）。 |
| **Q3** | 为什么大状态空间必须“按需展开”而绝不能预建？ | 组合爆炸问题（如 15-puzzle 需 160TB 内存，24-puzzle 状态数超全宇宙恒星）。必须采用隐式表示，在线按需生成后继。 |
| **Q4** | 图搜索（Graph Search）相比树搜索多做了什么？ | 增加了 Explored 集合记录已展开状态，用于去重；但可能引发更优路径后到达已探索节点的代价重开（Cost Reopening）难题。 |
| **Q5** | 为什么 UCS 必须在节点“出队”时才进行目标测试？ | 若在子节点生成入队时提前终止，该节点可能并非当前最优路径，Frontier 中可能仍存在累积代价更低、尚未延伸到目标的更优候选路径。 |
| **Q6** | 为什么 IDS 的浅层重复搜索开销非常小？ | 搜索树节点数随深度呈指数增长（深层节点占绝大多数）；数学求和表明额外开销仅约为 $\frac{1}{b-1}$（$b=10$ 时仅多约 $11\%$），换来 $O(bd)$ 线性极低空间。 |
| **Q7** | 贪心最佳优先搜索为什么“快而不优”？ | 仅依据 $f(n)=h(n)$ 排序，只看未来预估，完全忽略已付出的累积代价 $g(n)$；启发式稍有偏差就会深陷绕路或死胡同。 |
| **Q8** | 什么是启发函数的可采纳性（Admissibility）？ | $h(n) \le h^*(n)$，启发函数永不高估真实剩余代价（乐观估计）。它是**树搜索 A\*** 保证最优解的充分条件。 |
| **Q9** | 什么是启发函数的一致性（Consistency）？ | 满足三角不等式 $h(n) \le c(n, a, n') + h(n')$ 且 $h(Goal)=0$。它保证 $f(n)$ 沿路径单调非减，是**图搜索 A\*** 首次出队即最优的充分条件。 |
| **Q10** | 一致性与可采纳性之间具有什么数学包含关系？ | **一致必然可采纳，但可采纳不一定一致。** 树搜索只需可采纳，图搜索必须一致性以避免代价重开。 |
| **Q11** | 如何利用“放松问题”构造可采纳的启发函数？ | 通过移除原问题中的部分物理约束构造简化问题；简化问题的最优解代价必然 $\le$ 原问题最优解代价，故天然构成可采纳的 $h(n)$。 |
| **Q12** | 解释启发函数“支配性（Dominance）”的含义？ | 若 $h_2(n) \ge h_1(n)$ 且均满足可采纳，则 $h_2$ 支配 $h_1$；使用 $h_2$ 展开的节点数必然小于等于 $h_1$，搜索剪枝效率更高。 |

## 本章方法论总结与后继展望

* **本章总结**：
  * 状态空间建模（把找路翻译为五要素）；
  * 盲搜框架（BFS 等代价、DFS 省内存、IDS 兼得二者、UCS 变代价）；
  * 启发搜索（贪心看未来，A* 兼顾过去与未来）；
  * 理论基石（放松问题构造，可采纳保树搜索最优，一致性保图搜索最优）。
* **下一章预告 · 约束满足问题（CSP, Constraint Satisfaction Problems）**：
  * 状态定义从「序列路径」演进为「变量赋值」；
  * 求解目标从「找一条代价最低的路径」转变为「找到一组满足所有相互约束的完整变量取值」；
  * 引入回溯搜索（Backtracking）、前向检验（Forward Checking）与约束传播（Constraint Propagation / AC-3）提前强力剪枝。
