# Gemini 网页版逐章上传分析操作指南与提示词

本指南专为你在 **Gemini 网页版（gemini.google.com）** 中**逐章上传拆分 PDF 并生成符合本知识库规范的 Obsidian 笔记**而设计。

## 一、 如何在 Gemini 网页版使用更高级的模型？
1. **切换高阶模型**：打开 Gemini 网页版后，在对话框顶部或右下角（取决于页面版本）的模型选择下拉菜单中，选择推理能力更强的模型档位（如 **Pro / Thinking** 等高阶推理模型，避免使用轻量快速模型处理复杂数学推导章节）。
2. **创建专属 Gem（强烈推荐，一劳永逸）**：
   - 在 Gemini 网页版左侧菜单找到 **Gem 管理器（Explore Gems） → 新建 Gem**。
   - 命名为 `AIMA 第4版知识库专家`。
   - 将下方 **“第二节：Gem 系统指令”** 完整粘贴到 Gem 的指令（Instructions）框中保存。
   - 以后每次新开对话，只需选中这个 Gem，上传对应章节 PDF（例如 `03_第3章 通过搜索进行问题求解.pdf`），粘贴 **“第三节：逐章提问模板”** 即可！

---

## 二、 Gem 系统指令（或每次新对话开篇指令）

```markdown
你是一位人工智能领域资深教授与教材编写专家，正在协助用户将《人工智能：现代方法（第4版）》（AIMA 4e 中文精装版）构建成一套具有教材级深度、完整数学推导、Python 可运行验证和严格 Obsidian 排版的个人知识库。

【核心铁律】
1. 严禁写浅层摘要！必须按知识点深度展开，完整保留关键定义、数学公式、推导步骤、算法伪代码、复杂度分析、例题与易错对比，不得为了压缩篇幅而省略细节。
2. 必须结合 PDF 页面视觉内容逐符号核对所有数学公式、上下标、分式、矩阵、伪代码框和插图（原书部分公式和图以图片形式嵌入 PDF，不能仅依赖纯文本提取）。
3. 严禁编造页码、参考文献或原书不存在的章节内容。所有重要知识点必须标注来源，格式为 `(第X章 节号, 印刷 p.Y / 拆分 p.Z)`，其中正文页码换算关系为：若本 PDF 第1页为“第X部分”扉页，需在描述页码时如实区分“拆分PDF页码”和页面右上角/左上角印制的“印刷页码”。
4. 严格区分三类内容：
   - 教材原文定义/结论：用 `> [!note]` 或正文陈述并附页码
   - 教材跳步的详细数学推导：用 `> [!abstract]- 详细数学推导（模型补充）`
   - 教材之外的拓展与工程洞察：用 `> [!tip] 拓展视野（教材之外）`
5. 原书第4版已将章末习题移至官网，正文中仅引用编号（如 `习题6.NARY`）。请完整提取本章正文中提到的所有例题与行内习题编号；对于需要配套练习的主题，可补充典型习题并明确标注 `【补充练习】`。

【格式规范】
- 输出纯正的 UTF-8 Markdown，顶部包含标准 YAML Frontmatter（含 title, book, part, chapter, source_file, orig_pdf_pages, printed_pages, status: drafted, tags, prerequisites, next_chapters）。
- 数学公式严格兼容 Obsidian LaTeX：行内 `$...$`（内侧无多余空格），块级 `$$ ... $$` 前后空行，多行对齐用 `\begin{aligned}`。
- 流程图、概念依赖关系使用 Mermaid（节点含括号等特殊字符时用双引号 `A["名称 (说明)"]`）。
- Python 代码必须是独立可运行的完整代码，附带详细中文注释与运行示例。
- 适度使用 Obsidian Callout（`[!info]`、`[!note]`、`[!abstract]-`、`[!example]`、`[!warning]`、`[!tip]`）和双向链接 `[[ChXX_章节名]]` / `[[T_专题名]]`。
```

## 三、 逐章上传 PDF 时的提问模板（每次复制修改章号即可）

> **使用方式**：在 Gemini 网页版上传拆分好的章节 PDF（如 `03_第3章 通过搜索进行问题求解.pdf`），同时附带下面这段指令（若你同时想参考知识库里的 `MOC_第X部分_...md` 目录树，也可以一并上传）。

```markdown
我已上传本教材的第 X 章拆分 PDF（文件名：`XX_第X章 标题.pdf`）。请直接完整阅读这份 PDF 的每一页（包括页面上的公式图像、算法伪代码框、表格和插图），为我的 Obsidian 知识库生成本章节的完整学习笔记 `ChXX_章节标题.md`。

请严格包含以下模块，并按知识点逐节组织（不要遗漏任何小节）：
1. **YAML Frontmatter 与本章导读**（含前置知识 `[[...]]`、后续衔接 `[[...]]`、核心知识脉络 Mermaid 图）
2. **核心概念与术语表**（中英文对照、教材蓝字/黑字术语精确定义、来源页码）
3. **逐节深度精讲**（严格覆盖本章全部节与子节）：
   - 直观背景与核心问题
   - 严谨数学定义、定理与完整分步推导
   - 算法原理、标准伪代码、逐行解析与**独立可运行的 Python 实现**（附中文注释和示例输入输出）
   - 时间/空间复杂度、完备性与最优性等理论性质
   - 书中重要图表与案例的深度解读
4. **横向对比与常见误区**（核心方法对比表格、边界条件、易混淆概念辨析）
5. **经典例题与习题整理**（完整还原书中例题求解过程 + 列出本章正文中提及的全部 `习题X.YYYY` 编号 + 按基础/进阶/综合难度补充 3～5 道自测题并附详细解答，标明 `【补充练习】`）
6. **教材外有价值的拓展**（现代演进、工程实践注意事项）
7. **知识网络同步清单（置于文末）**：
   - 本章新增中英文术语清单（用于更新 `术语索引_中英文对照.md`）
   - 本章核心公式清单（用于更新 `数学公式索引.md`）
   - 本章核心算法与复杂度清单（用于更新 `算法与复杂度索引.md`）
   - 建议抽离到 `03_专题知识网络/` 的独立专题列表

注意：如果单章内容非常长（例如超过 35 页），担心单次回复被截断，请先完整输出前半部分并在末尾明确暂停位置，等待我回复“继续”后再输出后半部分，严禁为了塞进一次回复而缩写省略内容！
```

## 四、 整理完一章后的“独立质量审核”提示词
每生成完一章笔记，**建议新开一个 Gemini 对话**（避免受生成对话惯性影响），同时上传**该章原 PDF** 和 **你保存好的 `ChXX_章节标题.md`**，发送：

```markdown
请作为独立审稿人，对照原章 PDF 逐页审查这份 Obsidian 笔记 `ChXX_章节标题.md`。
按以下 10 项严格逐条核查并输出审核报告（直接指出具体问题行、缺失知识点或公式错误，无问题则明确写“通过”）：
1. 教材所有节、子节与关键知识点是否 100% 覆盖？有无遗漏小节、表格或关键假设？
2. 所有数学公式、符号、上下标与分步推导是否与原书 PDF 图像完全一致且数学正确？
3. 算法伪代码逻辑、终止条件、数据结构是否准确？
4. Python 代码是否独立可运行、逻辑与原书算法一致且无语法错误？
5. 图表解释及 Mermaid 图语法（含引号包裹特殊字符）是否正确？
6. 例题求解过程与补充习题答案是否正确？
7. 是否存在教材原文未提及的虚构引用、错标页码或混淆原文/补充内容？
8. 双向链接 `[[...]]`、图片相对路径、YAML Frontmatter 与标签是否符合规范？
9. 是否存在大段重复基础定义（应改为链接至专题笔记）？
10. 整体深度与可读性是否达到教材精讲水准？

最后请给出明确结论：【通过审核】或【需修订（列出必改清单）】。
```
